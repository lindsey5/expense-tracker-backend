# Product Requirements Skill

## Purpose

Use this skill before writing code. It turns a rough idea into clear behavior, scope, and acceptance criteria.

## Best Practices

- Identify the user roles first.
- Define the main user workflows.
- Separate must-have features from nice-to-have features.
- Write acceptance criteria in observable terms.
- Clarify edge cases before implementation.
- Keep requirements small enough to ship incrementally.

## Project-Start Checklist

- What problem does the app solve?
- Who uses it?
- What are the core screens or API resources?
- What data must be created, read, updated, and deleted?
- What permissions are needed?
- What should happen when something fails?

## Common Mistakes

- Starting with database tables before workflows are clear.
- Building optional features too early.
- Leaving response shapes undefined.
- Ignoring error states.

## Definition Of Done

- Core workflows are listed.
- Feature scope is clear.
- Acceptance criteria exist.
- Open questions are documented.
