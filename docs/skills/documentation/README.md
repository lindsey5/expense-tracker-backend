# Documentation Skill

## Purpose

Use this skill to keep project knowledge easy to recover across sessions.

## Best Practices

- Document decisions, not obvious code.
- Keep setup steps current.
- List required env vars without values.
- Record known gaps honestly.
- Keep API behavior discoverable through Swagger/DTOs.

## Project-Start Checklist

- How does a developer run the app?
- How are tests run?
- What env vars are required?
- What architecture decisions matter?
- What is intentionally not implemented yet?

## Common Mistakes

- Writing long docs nobody updates.
- Including secret values.
- Documenting wishes as if they are implemented.
- Forgetting Windows-specific commands when working on Windows.

## Definition Of Done

- Setup is documented.
- Commands are documented.
- Env names are documented without values.
- Known gaps are visible.
- Docs match the current project.
